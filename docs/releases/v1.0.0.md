# StewardBench v1.0.0 release notes

StewardBench is a Docker-deployed, product-independent evaluation platform for
repeated network-operations question runs. Its v1 workflow imports and curates a
question corpus, executes supported product APIs through versioned adapters,
preserves immutable evidence, supports human GOOD/BAD review, creates historical
baselines, compares controlled reruns, and exports CSV/JSON evidence.

The supported topology is one Django/Gunicorn web container, one PostgreSQL-
backed worker container from the same image, and PostgreSQL 17.11 with durable
storage. Migrations are an explicit deployment step. `opss-performance-v1`
classifies externally observed response latency independently from answer
quality; target-reported tokens and runtime/model identity remain optional.

OpsSteward v1.0.4 and v2 development use separate source-derived `/chat` and
`/version` contracts with session-cookie authentication. Their release status
is `LIVE_CERTIFIED` only after credential-bound calls against each real target.

Known limitations:

- semantic comparator and LLM judge providers may be `Not configured`;
- OpsSteward conversation lifecycle is not live-certified;
- source rows 197–202 retain deferred conversation grouping;
- token/runtime telemetry exists only when the target reports it;
- v1 is Docker-only and has no automatic release gating, MCP, or user-facing
  CLI.

Kubernetes and CI-triggered evaluation remain v2. MCP, CLI, mature automation,
and broader intelligence remain v3+.

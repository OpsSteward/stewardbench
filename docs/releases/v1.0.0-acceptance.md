## Performance, telemetry, and structured-answer findings

The deterministic inventory path demonstrated structured capture with target
token telemetry absent (`NULL`, not inferred zero). A retained real
LLM/KB-mediated policy response demonstrated optional telemetry: approximately
42.387 s external latency, 42.335 s target total, 42.286 s model-serving,
19.318 s MCP, three calls, and 5,393 / 616 / 6,009 input/output/total tokens;
it was correctly classified BAD under unchanged `opss-performance-v1` policy.
These are valid observations of OpsSteward v1.0.4, not StewardBench defects.

M11 found and repaired a narrow normalization defect: valid source-derived
nested `performance.ollama` and `performance.model_serving` mappings were
being reported as malformed scalar timings even though their useful telemetry
was captured. The normalizer now recognizes those documented nested envelopes
and retains validation for actual malformed scalar timings. Historical immutable
evidence was not rewritten. New real evidence has no false
`malformed_timing_*` diagnostics.

## Security and trust boundaries

- The real session credential was never printed, inspected, rotated, stored in
  the repository, or included in target records.
- A credential-aware scan of a live database dump, raw request/response and
  evidence/export material, and Compose logs found zero matches without
  revealing the value.
- `.env` is ignored and untracked. A full tracked Git-history blob scan found
  zero matches for the real credential. The repository's synthetic canary is
  the only generic secret-pattern fixture.
- Structured target output, including table cells and unknown payload fallback,
  is escaped before rendering. CSV injection protection, ADMIN/OPERATOR
  enforcement, no public registration, and documented production debug posture
  remain covered by the acceptance catalog.

## Known StewardBench limitations

- Semantic-comparator and LLM-judge providers are not configured.
- OpsSteward conversation lifecycle is not certified.
- PROFILE source rows 197–202 remain unresolved; target token telemetry is
  target-dependent.
- v1 is Docker/PostgreSQL deployment only; it has no MCP, CLI, CI-triggered
  evaluation, automatic release gating, or Kubernetes support.
- Create-Question usability improvements (GitHub issue #1 and related field
  help/progressive disclosure observations) and unintegrated logo/icon assets
  are v1.x follow-up work.
- Application build identity remains configuration-dependent; release Git and
  image identity are authoritatively recorded by this artifact and `v1.0.0`
  tag rather than fabricated in runtime exports.

OpsSteward v1.0.4 answer quality, latency, planner behavior, and token usage
are evaluated-target observations. They are intentionally preserved for future
comparison and are not listed as StewardBench limitations.
